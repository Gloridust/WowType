# 评测数据与基线数字

这里放公开语料生成的评测用例怎么来、以及当前基线，方便改排序/LM 时对比。

## 生成用例

```bash
# Tatoeba 中文句子（CC BY 2.0）：https://downloads.tatoeba.org/exports/per_language/cmn/
python3 tools/make_corpus_eval.py --tatoeba cmn_sentences.tsv.bz2 \
    --split /tmp/train.tsv:3000 /tmp/test.tsv:500

# 或者一行一句的纯文本
python3 tools/make_corpus_eval.py --text sentences.txt --out cases.tsv --count 2000
```

## 跑评测

```bash
# 词库 + 词级 LM
cargo run --bin wowtype-eval -- --lexicon lexicon.tsv --eval /tmp/test.tsv \
    --lm words.lm --k 1

# 再加上字级神经语言模型（从本机微信输入法里取，见 tools/install_wetype_nnlm.py）
cargo run --bin wowtype-eval -- --lexicon lexicon.tsv --eval /tmp/test.tsv \
    --lm words.lm --nnlm nlrgpt2_nnlm.bin --k 1
```

## 基线（本机 macOS，debug 构建，2026-11）

词库：雾凇拼音 + jieba 词频合并（936,662 条），LM：`words.lm`。

| 用例集 | 不开 NNLM | 开 NNLM |
|---|---|---|
| Tatoeba 留出 500 句 | 61.4% | **65.2%** |
| Tatoeba 留出 100 句 | 53.0% | **62.0%** |
| 另一组留出 100 句（与训练不重叠） | 68.0% | **75.0%** |
| 手写日常句 138 句 | 84.8% | **91.3%** |

其他观察：

- `--beam 32/48` 基本不变（61.6%）
- `--lm-weight 0.5~0.7` 在 Tatoeba 上略好，但日常句会掉；默认 1.0 是折中
- 500 句里约 31% 的正确句子连 top50 都进不去：瓶颈是覆盖/切分，不是排序权重

## 三件套基线（2026-11，本机）

在「词频融合 + 自适应 LM 权重 + 领域 LM 混合」都打开时：

| 用例集 | 基线 | 三件套 |
|---|---|---|
| Tatoeba 留出 500 句 | 61.4% | **67.6%** |
| 另一组 1000 句留出 | 60.3% | **65.0%** |
| 手写日常句 138 句 | 84.8% | **87.0%** |

具体配置：

- 词库：雾凇 + jieba 合并 + Tatoeba 训练侧词频融合（权重 0.3）
- LM：`words.lm` + `--domain-lm`（当时叫 `--lm2`；Tatoeba 训练侧训的 0.5MB 小模型，权重 0.4）
- 自适应 LM 权重默认开

再叠加 NNLM 重排（`--nnlm nlrgpt2_nnlm.bin`）：500 句 top1 **69.2%**（比不加 NNLM 的 67.6% 再高 1.6）。

## 失败归因（500 句，三件套）

- top1 67.6%，top50 74.2%，剩 129 句进不了前 50
- 111/129 只差一个同音字；其中 19 句是「他/她」代词（无上下文不可判定）
- 可对齐的 86 句里：她→他 14、他→她 5、莉→丽 3，其余分散（花/话、时/是、甚/什、鱼/与…）
- 语料 ∩ CC-CEDICT 只挖出 32 个台湾用词变体（义大利、帐单、咖哩…），不值得默认加

结论：剩下的主要是同音消歧长尾，靠更强的上下文模型，不是词库覆盖。

### 试过但没用的

- 调高 NNLM 特征权重（head_word_nnlm=2/4）：100 句 65.0% -> 64.0% -> 60.0%，反而更差
- 从语料补 159 个专名/复合词（玛莉、莱拉、鲍伯…）：500 句 top1 不变（67.6% -> 67.6%）
- 按输入长度调 LM 权重（#200），见下一节：长度上没有规律，最好的「按长度分段」也不比一个常数强

## 按输入长度调 LM 权重：负结果（#200，2026-11）

#200 想在 33 个字母以内把 `beam.lm_weight` 乘 0.5。33 个字母几乎盖住所有日常输入，实际上是全局减半；
阈值又是在报告结果的那 500 句上挑的。这里换成「调参集、留出集分开」重做一遍。

做法：`make_corpus_eval.py` 默认种子按顺序切 `--split train.tsv:3000 test.tsv:500 tune.tsv:2000 heldout.tsv:2000`，
只在 tune 上挑参数，heldout、test（#200 自己报数的 500 句）、手写日常句 138 句只用来验。
数据包 2026.11.11-3（雾凇 929,405 词 + `words.lm` + english.txt），release，每个输入取前 10 个候选看 top1。
每句在 `lm_weight` = 0.3 … 1.4 各跑一遍，任何「按长度给权重」的方案都能直接从这张表上算。

全局常数（top1 对的句数 / 总数）：

| lm_weight | tune | heldout | test | 日常句 |
|---|---|---|---|---|
| 0.5 | 1227/2000 | 1209/2000 | 308/500 | 116/138 |
| 0.7 | 1235/2000 | 1224/2000 | 310/500 | 119/138 |
| 0.8 | 1237/2000 | 1218/2000 | 312/500 | 118/138 |
| 1.0（现在） | 1196/2000 | 1194/2000 | 305/500 | 119/138 |
| 1.2 | 1149/2000 | 1134/2000 | 292/500 | 117/138 |

按字母数分段，每段最好的权重（句数 / 该段总数）：

| 字母数 | tune 最好 | heldout 最好 | heldout 上 1.0 |
|---|---|---|---|
| 1–15 | 0.7（216/294） | 0.7（214/287） | 205/287 |
| 16–25 | 0.9（495/757） | 0.7（503/755） | 489/755 |
| 26–35 | 0.8（341/569） | 0.7（329/558） | 324/558 |
| 36–45 | 0.7（142/244） | 1.0（120/253） | 120/253 |
| 46 以上 | 0.6（52/136） | 0.7（60/147） | 56/147 |

各段都在 0.6–0.9 之间来回跳，没有「越短越低」：最长那段反而最低，36–45 在两边一个 0.7 一个 1.0。
在 tune 上拟合的方案拿到别的集上（括号里是比 1.0 多对 / 多错的句数）：

| 方案（只在 tune 上挑） | heldout | test | 日常句 |
|---|---|---|---|
| 常数 0.8 | 1218（+47/−23） | 312（+14/−7） | 118（+2/−3） |
| 分两段：42 个字母以内 0.8，以上 0.5 | 1217（+49/−26） | 309（+15/−11） | 118（+2/−3） |
| 每段各用 tune 上最好的 | 1214（+42/−22） | 311（+14/−8） | 119（+2/−2） |
| #200：33 以内 0.5，36 以上 1.0 | 1211（+69/−52） | 311（+22/−16） | 116（+4/−7） |

结论：按长度分段不比常数好，#200 不合。全局把权重降到 0.7–0.8 在 Tatoeba 上是真的有用
（heldout +47/−23，符号检验 p≈0.006），但日常句持平或少 1 句，而且会影响所有输入，要单独评估
（再加上文、万象词库、简拼这几组）以后再定，不在这里改。

#200 还有个实现问题：`make_candidate` 减句首分时用的是没乘系数的 `lm_weight`，单音节的句首分多减了一半，
单字顺序乱了（`shi` 的「十」掉到第 9，`bu` 的第一个成了「部」）。以后要按输入调权重，整条链路要用同一个值。
（常数权重下没有这个问题：加句首分和减句首分乘的都是 `beam.lm_weight`（ef5def8）。
`single_syllable_ranking_ignores_lm_weight` 钉住了：权重 0.5 / 0.7 / 1.5 下单音节的候选顺序和分数都和 1.0 一样，
改回不乘权重这个测试就挂。）

## 全局 LM 权重在现在的词库上重测：不改，还是 1.0（2026-11-14）

上一节说全局 0.7–0.8 在 Tatoeba 上有用、要单独评估。词库后来默认融了 Tatoeba 语料词频（#205，留出 +2.3 点），
所以在现在的默认词库上从头再测一遍。

做法：

- 词库：同一份 rime-ice（927e1cf）、`words.lm`（lm-2026.11.09）、english.txt，release，`--max 10` 取 top1。
  - 「发布」：`scripts/make-data.sh` 默认构建。它融的 `data/tatoeba-freq.tsv` 是从全部 89248 句 Tatoeba 挖的，
    **包括下面的 tune、heldout、test**，在 Tatoeba 各组上的数字偏乐观，只作参考。
  - 「干净」：同样的融法，但语料换成 Tatoeba 去掉 test、tune、heldout 和日常句之后的 84685 句
    （`WOWTYPE_CORPUS`，和 docs/DATA.md §3.3 的做法一样）。选参数、报 Tatoeba 留出都用它。
- 用例：和上一节同一次切分（`make_corpus_eval.py` 默认种子，`train:3000 test:500 tune:2000 heldout:2000`）。
  只在 tune 上扫权重、取 tune 上最好的；别的组都只跑 1.0 和选出来的那个值，heldout 只跑这一次。
- 「+/−」是逐句比较（1.0 错、新的对 / 1.0 对、新的错），p 是双侧精确符号检验。

tune（2000 句，top1 对的句数）：

| lm_weight | 0.5 | 0.6 | 0.7 | 0.75 | 0.8 | 0.85 | 0.9 | 1.0 | 1.1 | 1.2 |
|---|---|---|---|---|---|---|---|---|---|---|
| 干净 | 1254 | 1276 | **1281** | 1272 | 1275 | 1274 | 1267 | 1249 | 1218 | 1199 |
| 发布（参考） | 1260 | 1281 | 1288 | 1276 | 1281 | 1280 | 1271 | 1253 | 1224 | 1202 |

tune 上最好的是 0.7（干净词库 +71/−39，p=0.003；0.8 是 +49/−23，0.85 是 +39/−14）。「取 tune 上最好的」是看到这张表以后定的；
下面只比了 1.0 和 0.7，0.8、0.85 没在别的组上跑过。

短输入（`--max 18`）：d、l、b、ma、bu、de、le、ni、wo、zai、he、shi（「十」第 5）、xz（现在）、nh、shim 在 0.5 / 0.7 / 0.8 / 1.0
下首选都一样，单音节的 18 个候选完全一样；xian 的「西安」第 5、tianqu 的「天气」第 2、nihao、diannao、yingai、shengme、zhongdi、
kyi、yongzwen、kaixin、jixu、fagei 的首选在 0.7 和 1.0 下也一样。

结论：**0.7 不比 1.0 稳，默认还是 1.0。**

- Tatoeba 上的好处还在，比融语料词频之前小一点：tune 上 0.7 比 1.0 多对的句数从 +39（1196→1235，上一节的旧词库）变成 +32（1249→1281），
  heldout 从 +30 变成 +24（词库、数据包不同，只能大致比）。
- 不一致：手写日常句掉 3 句、一句没多对（发布词库和双拼是同样三句：「周末一起去爬山吧」「我们在哪里见面」「我在看一本很有意思的书」；
  混了领域 LM 时掉的是另外三句）；开着 NNLM 时 heldout 只剩 +48/−39（p=0.39）；混了领域 LM 反而掉（+39/−59，p=0.054；
  领域模型的分也在 `lm_weight` 里，跟着一起被压低）；刚学过的整句在 0.7 下 +4/−8（用户搭配的加分在 `LearnedLm` 里，也乘了这个权重）。
- 简拼、中低频词这几组涨得多，但它们的答案就是「词库里最常用的那个同音词」，降 LM 权重就是更信词频，这个涨幅有一部分是自证，
  不能当成用户打字会变好的证据。

要再试的话，先把用户搭配的加分、领域模型挪出 `lm_weight` 再比，0.8、0.85 也要在日常句、NNLM、领域 LM 上跑，而且日常句不能掉。
上文特征（`context_bigram_score`，排序权重 1.0）没有乘 `lm_weight`：权重是 1.0 时两边一致；试过在 0.7 下也乘上，
和 0.7 不乘比：上下文 533 条 +5/−3、test 后半句 +6/−2、日常句后半句 +2/−0，都在噪声里，默认不改权重就不用动它。

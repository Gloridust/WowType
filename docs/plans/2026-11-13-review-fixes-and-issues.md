## 第一部分：审查发现

审查范围说明：重点读了核心的 C 接口（`session_ffi.rs`）、互译流程、自定义词、本地翻译、原子写入、最近用过的 emoji；两个外壳（`wowtype_engine.cpp` 改了约 1200 行、`Composer.swift` 约 500 行）只抽查了关键处。**外壳这两个文件值得再单独审一遍**（见 P7）。

### F1 猜拼音遇到叠字失败（正确性，小）

- 位置：`core/src/lexicon.rs` 的 `guess_pinyin`，`chars.iter().position(...)` 那一行。
- 现象：词里有重复的字、整词又不在词库里时（妈妈咪、试试看、看一看），返回 `None`，设置里加自定义词时拼音不自动填。
- 原因：一趟扫词库时，用 `position` 把词库里的字对到「词里第一个相同的字」的槽位，第二个相同的字的槽位永远是空的，逐字拼的时候就判成「有猜不出的字」。搬进核心之前 Swift 是一个字查一次，没有这个问题，是 #157 引入的。
- 修法：槽位按「不同的字」建，而不是按位置建。
  1. `uniq: Vec<&str>` 存词里出现过的不同的字，`best: Vec<Option<(f64, &[u8])>>` 长度 `uniq.len() + 1`（0 号还是整词）。
  2. 扫词库时 `uniq.iter().position(...)` 对到槽位。
  3. 拼结果时按词里字的顺序，每个字去 `uniq` 里找自己的槽位取读音。
- 测试：`guess_pinyin_from_lexicon_text` 加「你你好」→ `ni ni hao`、「好好」（整词不在）→ `hao hao`；`macos/Tests/main.swift` 的猜拼音用例加一条叠字的。
- 验收：`cargo test`、`macos/test.sh` 通过。

### F2 一个输入框会取消另一个输入框的翻译（正确性，中）

- 位置：`core/src/session.rs` 的 `clear_translation` / `poll_translation`（`translator.cancel()`），`core/src/translate.rs` 的 `Translator::cancel`。
- 现象：翻译器全进程共用一个。输入框 A 在「译」里攒着原文、发过请求（`requested = true`）；用户到输入框 B 发起翻译（`start` 会顶掉 A 的任务）；之后 A 被清空（Esc、失去焦点、换翻译器）时调 `cancel()`，把 B 正在跑的请求杀掉，B 的译文不来，要等原文再变才重发。
- 原因：`cancel()` 不认是谁的请求，`requested` 只表示「我发过」，不表示「现在跑的是我的」。文件头注释写的「每个输入框的会话只取消自己发的请求」没有做到。
- 修法（#176，没动 C 接口）：会话记下自己发出去的那句原文（`requested: Option<String>`），清空时只在翻译器上跑的还是这句话才取消。
  - `TranslateBackend` 加 `cancel_source(source)`，默认实现是先 `poll` 看原文、一样才 `cancel`。会话都在同一个线程上调翻译器（插件的事件循环、macOS 的主线程），先看再取消之间不会有别人 `start`，所以 macOS 的函数表不用改。
  - 核心的 `Translator` 自己实现，在锁里比对。
  - 原来计划的「请求带编号、改函数表」不需要了。
  - 两个输入框原文一模一样时仍会互相取消（分不出是谁的），代价是下一次轮询重发。
- 测试：`clearing_one_session_keeps_another_sessions_request`（改之前会挂）、`cancel_source_only_cancels_that_request`。

### F3 模型坏了时 llama-server 连起三次（体验，小）

- 位置：`core/src/llama.rs` 的 `acquire`，`if exited && attempt < 3`。
- 现象：#169 为了治「端口被别人抢了」加的重试，把所有「起来就退出」都当成抢端口。模型文件损坏、版本不兼容时，llama-server 载入几秒后退出，要重复三次才报错，等待时间约三倍，这期间别的会话也卡在条件变量上。
- 修法（#177）：按「起来多久就退出」区分。3 秒内退出当作端口被抢，换端口重试（最多 3 次）；更晚才退出的（载入模型以后）直接报错。
  - 没用「退出后试绑端口」：占端口的进程要是在去试之前就没了（慢机器上很可能），会判成「不是端口问题」、不重试，#169 治的偶发失败又回来。
  - 3 秒是给忙的 CI 留的余量（并行测试时假服务的 Python 启动就要一两秒）。
- 测试：假服务每次启动往文件里记一行，数启动次数：马上退出的起 3 次后报错；4 秒后才退出的只起 1 次；第一次马上退出、第二次正常的重试后能用。
- 备注：根治要让 llama-server 自己挑端口再报回来（`--port 0` 加读日志），依赖 llama.cpp 的输出格式，不做。

### F4 选 emoji 时在按键线程上 fsync（性能，小）

- 位置：`core/src/recent_emoji.rs` 的 `remember`。
- 现象：每次选 emoji 都 `create_dir_all` + 整份写 + `sync_all` + 改名，而且拿着全局锁。慢盘、网络盘上按键会卡一下。
- 修法：这份文件丢了也无所谓（最多 18 个 emoji），不需要落盘保证。
  1. `fsutil` 加 `write_replace(path, bytes)`：先写临时文件再改名，但不 `sync_all`。`user.tsv`、`history.tsv`、词库快照照旧用 `write_atomic`。
  2. `remember` 用 `write_replace`（#177）。没去掉锁里写文件：去掉刷盘以后写 18 行很快，挪出锁收益不大。
- 验收：`cargo test`；行为不变。

### F5 存盘中途被杀会留下临时文件（整洁，小）

- 位置：`core/src/fsutil.rs` 的 `temp_path`（`.{name}.{pid}.tmp`）。
- 现象：进程在创建临时文件和改名之间被杀（注销、升级、OOM）时，带进程号的临时文件留在数据目录里，进程号不会再出现，没人清。
- 修法：`write_atomic` 成功以后顺手清一次：列出同目录里 `.{name}.*.tmp`，进程号不是自己、修改时间超过 1 小时的删掉。失败不报错。
- 测试：建一个假的旧临时文件（把 mtime 改到 2 小时前），存一次以后它没了；刚建的（别的进程正在写的）不动。

### F6 `toolbar` 的旧外壳兜底是多余的（整洁，很小）

- 位置：`core/src/session_ffi.rs` 的 `to_config`，`toolbar: self.toolbar != 0 || size <= offset_of!(toolbar)`。
- 原因：`read_sized` 是从 `Default`（`toolbar = 1`）开始、只盖上外壳给的那几个字节，旧外壳给的短结构体本来就读得到默认值，后半句永远不起作用。
- 修法：改成 `toolbar: self.toolbar != 0`，注释写清「短结构体没给的字段是 Default 的值」。可以和 F2 放一个 PR。

**#172 弃车保帅打不出来（数据，很小）→ #175**
- 查证：发布的词库里只有 `diu ju bao shuai 丢车保帅`，没有「弃车保帅」。现在 `qijubaoshuai` 首选是「棋具抱摔」。
- 做法（#175）：弃车保帅、丢车保帅、舍车保帅、丢卒保车、弃卒保车都收 jū、chē 两个读音，词频 1000（10000 会把简拼 qcbs 抢走，1000 和 100 不会）。`tools/add_hotwords.py` 改成同一个词可以写几行读音、词库里没有的读音都加；顺带改正热词表里写错的「微调 wei diao」「调休 diao xiu」。数据修订号不用加（`pre-release` 的修订 4 还没发）。

**#170 Ubuntu 24.04 上语音浮条不显示（bug，中）**
- 分析：浮条是 GNOME 扩展 `voice.js` 画的。扩展启动时在会话总线上占一个名字，插件看到这个名字就**只发信号、不再自己在候选框里画**提示。用户看到「什么都没有、关掉主题后正常」，说明名字占上了，但 `voice.js` 在 GNOME 46 上画的时候出错了。
- 做法：
  1. 在 Ubuntu 24.04（GNOME 46）上复现，看 `journalctl --user -b /usr/bin/gnome-shell | grep -i wowtype` 的报错。`voice.js` 用了 `Mtk.Rectangle`、`Clutter.Timeline({actor})`、`get_monitor_index_for_rect`，这几处在 45 / 46 / 47 之间变过，先看它们。
  2. 不管原因是什么，加一道保险：扩展画成功了才回一个「画了」的信号（或者把占名字挪到第一次画成功以后）；插件发了状态、一小段时间里没收到回执，就退回自己在候选框里画。这样扩展再坏也不会「什么都不显示」。
- 先回复用户要一份上面的日志。

**#160 双拼下用不了 v 计算器（功能，小到中）**
- 难点：双拼里 `v` 是声母键（多数方案是 zh），`v` 后面按数字本来是「选第几个候选」。全拼里 `v` 不是声母、没有候选，所以没有冲突。
- 做法：双拼时用**大写 V**（Shift+V）进计算器：`V12345.67` 出大写金额，`V1+2*3` 算算式。小写 `v` 的行为不变。会话里 `calc_active` 现在直接排除双拼，改成「双拼时要求第一个字符是大写 V」。工具栏同理可以用 `V` + 空格，这次先不做。
- 设置界面「双拼时不可用」改成「双拼时用大写 V」。
- 测试：`session_keys.rs` 加双拼下 `V1+2` → 3、`v1` 仍然是选第一个候选。

**#143、#87（后半）自定义中英切换键、互译单独的键（功能，中）**
- 做法：两个新设置，类型和 `EmojiKey` 一样（fcitx5 键名）：`ToggleKey`（切中 / 英）、`TranslateKey`（进 / 出「译」），默认都留空。外壳认出快捷键以后调 `wowtype_session_set_mode`（Linux 再同步全局的 `asciiMode_` / `translateMode_`）。
- 注意：Ctrl+空格是 fcitx5 默认的「切换输入法」，fcitx5 先处理，WowType 收不到。设置界面要像现在提示 Shift 冲突那样提示，并说明可以在 fcitx5 那边改掉。macOS 上 Ctrl+空格是系统的切输入源，同样提示。
- 三端都要加（`spec/config.json`、插件、Linux 设置、macOS `Config.swift` 和设置窗口）。
- **结果（11-14）**：只做了 `ToggleKey`（#185），进出互译的键暂缓（代码留在分支 `parked/translate-mode-key`）。
- **结果（11-14 晚）**：`TranslateModeKey` 在 `feat/platform-keys` 重做：两个快捷键都交给会话（`KEY_ACTION_TOGGLE_MODE` / `_TOGGLE_TRANSLATE`），在「译」里按互译键回到进来前的模式，设了互译键时单按 Shift 只切中英。按平台定切换方案：macOS 设置先说系统的 中/英 键，预设去掉两端系统都占着的 Ctrl+空格（预设：`Control+Shift+space`、`Control+Shift+Y`）。

**#129 左右键在拼音里移动光标（功能，大）**
- 做法：会话里加输入光标（现在恒在末尾）：
  1. `Session` 加 `caret: usize`（在还没选词那段输入里的字节位置）；字母插在光标处，退格删光标前一个。
  2. 横排时：光标不在最右，右键右移；在最右，右键才是下一个候选。左键同理（在最左才是上一个候选）。竖排时左右键只管光标（上下键管候选）。
  3. `frame.preedit_cursor` 已经有，按光标位置给；分音节显示（`ni'hao`）时要把原始位置换算到显示位置。
  4. 做成设置项「方向键移动拼音光标」，**默认关**，稳定后再考虑默认开。
- 已知限制：GNOME 的 kimpanel 扩展拿不到光标位置，面板上不显示光标；在回复里说明。
- 放在 P5，单独一个 PR，要补不少按键用例。
- **结果（11-14）**：做成了设置「方向键」（`ArrowKeys`）的两种用法（#188）：「都用来选词」（默认，和原来一样）、「左右键移动光标」（↑ ↓ 选词、到一页两头接着翻页，← → 只管光标）。上面第 2 条「到了最左最右再去挑候选」没有做。

**#161 常用字前置（功能，小；先确认）**
- 理解：粤语用户常用一些普通话里的生僻字，每次都要翻很多页。现在「选过最多的那一个字」会排到第二个，别的选过的字还在原位。
- 做法：单音节输入时，**所有选过的字**按次数排到前面（紧跟第一个候选），不只是最多的那一个。`promote_picked` 里单字的分支改成把 `history_use_count > 0` 的字稳定排序提到位置 1 起。
- 先回复确认是不是这个意思；是的话很小，可以和 F1 一起做。

**#84 deepin 25 安装包（打包，中）→ #182**
- 容器镜像查过（`linuxdeepin/deepin:25`、`:23`，只有 amd64）：deepin 25 是 fcitx5 5.1.12、libadwaita 1.5、glibc 2.38；deepin 23 是 5.1.11，同样的 libadwaita 和 glibc。
- 做法（#182）：CI 包矩阵加 `deepin23`、`deepin25`（25 上编的包要 fcitx5 ≥ 5.1.12，23 装不上，所以分两个）；`install.sh` 和自动更新按代号（crimson / beige）或版本号认 deepin，在「不可变系统」之前认出来（deepin 25 的磐石系统基于 OSTree，官方说 `apt-get install` 会转给 `deepin-immutable-ctl`）；deepin 上不装 im-config、fcitx5-config-qt，不切输入法框架。
- 容器里照 CI 跑通：按键测试、打包、一键安装、设置自检。**真机上磐石系统开着能不能装本地 .deb 没验证**，发版后请报告的人试。

### 老 fcitx5：让用户升级，还是我们支持 5.0

问题：Ubuntu 22.04（#125）、UOS 20（#159）这类系统的 fcitx5 低于我们要求的 5.1，能不能直接建议他们升级 fcitx5？

**查到的（2026-11-13，在 ubuntu:22.04 容器里实测）：**

1. **22.04 官方源里升不上去。** 加上 jammy-backports，`fcitx5`、`libfcitx5core-dev` 都只有 5.0.14。要 5.1 只能用第三方 PPA，或者自己编 fcitx5、fcitx5-gtk、fcitx5-qt、fcitx5-modules 一整套。这是把整个输入法框架换掉，影响所有应用，出了问题用户自己很难退回来——**不适合作为给普通用户的建议**。
2. **我们的插件离 5.0 很近。** 5.1 这个下限是 e9582d7（打包那次）定的项目基线，不是用到了哪个 5.1 才有的接口。把下限改成 5.0 编译，只有两处要改：
   - `fcitx5-addon/conf/wowtype-addon.conf.in` 写死了 `0=core:5.1.0`，照 fcitx5 的依赖检查 5.0 应该会拒绝加载插件（没单独验证：实测时已经改成了 5.0.0）。改成 CMake 按实际下限填。
   - `wowtype_engine.cpp` 用了 5.1 才有的 `Key::digit()`（一处），换成 `key.sym() - FcitxKey_0`（前面已经判断过 `isDigit()`）。
   - 其余都能编，包括 #166 用的 `InputMethodSwitchedReason::CapabilityChanged`。5.1.11 才有的 `showCustomInputMethodInformation` 本来就有 `WOWTYPE_HAVE_CUSTOM_IM_INFO` 兜底。
3. **按键测试在 5.0.14 上几乎全过。** 用真词库和语言模型跑 `scripts/addon-test.sh`（核心带语音）：277 条通过，设置契约 572 项通过，只挂 1 条：
   - 「互译：密码框里照常打中文」：5.0.14 没有「密码框也用输入法」这个设置（头文件里查过，没有 `AllowInputMethodForPassword`），测试进不了密码框。5.0 上密码框里一律是键盘布局，WowType 根本收不到按键，不会翻译，行为没问题。降到 5.0 时这条测试要按版本跳过。
   - （第一次没带语音编译时另外挂了 4 条语音的，带上语音就过了，是编译选项的问题，不是 5.0 的。）
4. **设置界面和 GNOME 扩展在 22.04 上都用不了。**
   - 设置界面要 libadwaita 1.5+，22.04 是 1.1.7。用户只能改 `wowtype.conf`，或者设置界面以后做降级（老 libadwaita 下少几个控件）。
   - GNOME 扩展（绿色候选框主题、语音浮条）的 `metadata.json` 写的是 GNOME Shell 45–51，22.04 是 GNOME 42，装不上。候选框会是 kimpanel / fcitx5 默认的样子，语音提示退回候选框里的文字。
   - 这两样升级 fcitx5 也解决不了。
5. **UOS 20 / deepin 20 预装的是 fcitx 4**，fcitx5 是 20.2.3 以后才进源的（deepin 维基）；源里的 fcitx5 是哪个版本没查到。deepin 25 的 fcitx5 版本也没查到。要请报告的人跑 `apt-cache policy fcitx5`。

**建议：** 不让用户升级 fcitx5，我们把下限降到 5.0。
- 代码改动很小（上面两处），可以单独一个 PR。
- 先只支持从源码编（`docs/INSTALL.md`、README 改成「fcitx5 5.0 或更新」，注明 5.0 上没有自定义的中 / 英提示气泡、设置界面要 libadwaita 1.5+、GNOME 扩展要 GNOME 45+）。按键测试里「密码框」那条在 5.0 上跳过。
- 要出 22.04 的安装包再加一格 CI（jammy，glibc 2.35，gcc 11 够 C++20），一键安装认 22.04。设置界面在 22.04 上怎么办要先定。
- **定了（2026-11-13）：先只放开源码编译** → #181。**后来改成出安装包** → #182：22.04（amd64、arm64）和 deepin 一起进 CI 包矩阵，设置界面给 GTK 4.6 / libadwaita 1.1 加了替身控件（新系统照用原生的），22.04 上只剩 GNOME 扩展用不了。插件清单要求的版本改成编译时 fcitx5 版本的「主.次.0」（现有安装包还是 5.1.0）；按键测试按 `globalconfig.h` 判断测哪种密码框行为；CI 加「源码安装 · Ubuntu 22.04」（不挡发版）。在 22.04 容器里按分支原样跑：按键测试 278 条全过；清单 22.04 上是 `core:5.0.0`、5.1 上是 `core:5.1.0`。22.04 的安装包以后再说。#181 已合进 pre-release：CI 里 22.04 这一项跑的是 5.0 的密码框分支，清单是 `core:5.0.0`。

**#87 五笔和互译单独的键**
> 下一版起可以用五笔了：「WowType 设置 → 输入 → 输入方案」里选「五笔输入」（86 版，码表来自 rime-wubi）。打满四码、只有一个字词时直接上屏，第五码顶字，空码有提示，候选后面显示还要打的码（这两项都能在设置里关）；不会打的字先按 `z` 再打全拼（`znihao`），候选后面就是它的五笔码。五笔的码位固定，选过的词不会调频，也不会进拼音的用户词库。计算器在五笔下用大写 `V`。
> 互译也有单独的快捷键了：「WowType 设置 → 输入 → 中英文切换 → 互译的快捷键」，可以选 Ctrl + Shift + Y（Mac 上是 Control + Shift + Y，默认不用）。按它直接进「译」，在「译」里再按回到原来的模式（中文或英文），打到一半的拼音会带进「译」接着打。设了它以后单按 Shift 只在中文、英文之间切，不再绕到「译」；没设时和现在一样，单按 Shift 在 中 → 英 → 译 之间切。要先在「翻译」页打开互译，没打开时、密码框里这个键照常交给应用。

**#143 自定义中英切换键**
> 下一版起可以另设一个切换中英文的键：「WowType 设置 → 输入 → 中英文切换 → 另设一个切换键」，可以选 Ctrl + Shift + 空格（默认不用；`wowtype.conf` 里的 `ToggleKey` 也能写别的键）。按它在中文和英文之间切，在「译」里按回到中文；单按 Shift 照常能用。互译另有一个快捷键，见 #87。
> Ctrl+空格没放进选项：它默认是 fcitx5「切换启用/禁用输入法」的键（macOS 上是系统「选择上一个输入法」的键），系统先拿走，WowType 收不到；不过它本来就在 WowType 和英文键盘（macOS 上是 ABC）之间切，当中英切换用也行。Linux 设置里选的键被 fcitx5 占着时会提示。
> macOS 上最省事的是系统自带的 中/英 键（大写锁定键）：在「系统设置 → 键盘 → 文字输入 → 输入法」点「编辑…」，打开「使用“中/英”键切换“ABC”输入法」，所有应用里都管用；WowType 设置「输入」页有按钮直接打开键盘设置。

**#129 方向键移动拼音光标**
> 下一版加了这个功能：「WowType 设置 → 常规 → 候选词 → 方向键」选「左右键移动光标」（默认是「都用来选词」，和现在一样）。选了以后 ← → 把光标移进打了一半的拼音，打的字母插在光标处，退格删光标前一个，Home、End、Delete 也管用；↑ ↓ 选词，到了一页的两头接着翻页，翻页也可以用 Page Up / Page Down 或设置里的翻页键。「译」里拼音显示在原文框里，没有光标；打五笔码时方向键照样选词。
> 已知限制：GNOME 的 Input Method Panel 扩展画不出编辑区里的光标，那里看不到光标在哪，打字、删除照常对。

**#160 双拼计算器**
> 下一版起双拼也能用计算器了：双拼里小写 v 是声母键，所以改用大写 V，比如 `V1+2*3` 出 7、`V12345.67` 出大写金额，按 = 上屏结果。全拼还是小写 v；五笔也用大写 V。

**#122 双拼时编辑区显示打的键**

**#156 单字母、短拼音的第一个候选**

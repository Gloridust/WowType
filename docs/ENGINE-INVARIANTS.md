# 排序不变量：和成熟输入法对照，以及「永远不许出现」的规则

这份文档回答一个问题：**为什么 `cehaohou` 会只剩「的好后」「得好后」两个候选，成熟的输入法为什么不会这样？**
然后列出 WowType 现在用来拦这类结果的不变量检查（`scripts/invariants.sh`，CI 里每次都跑），
这次查出来、修好了的违反，和还没修、建议怎么改的地方。

引擎本身的设计见 [ENGINE.md](ENGINE.md)；排序评测（top1 命中率）见 [tools/eval/README.md](../tools/eval/README.md)。

用户定的规矩，原话：「按键纠错逻辑我觉得应该是添加可疑的候选词，而不是替代原候选词吧」。这份文档把它当成头一条不变量：
**纠错只能往候选里加东西，不能删掉、也不能盖过照着打的字母读出来的东西**（照着打的读法，和照着打的音节的字、词）。
补全、简拼、模糊音、双拼、神经语言模型重排也拿同一条规矩查了一遍（第 6 节）。

## 1. 起因

72bf8e2 修了 `cehaohou`（测好后）：接着「我本地」打时只出「的好后」「得好后」。三处原因叠在一起：

1. 束搜索剪枝按「末词」合并状态，不看纠错处数：纠错的「的 | 好」把照着打的「测 | 好」并掉了，照着打的读法走不到底；
2. 排序让纠错出来的候选排到照着打的读法前面：纠错是一个固定罚分（`typo_cost` = 8），「的」「得」的词频和神经语言模型分数高得多，罚分拦不住；
3. 神经语言模型的分数以纠错出来的路径为基准归一，照着打的整句全被扣十几分。

根子上的问题是：**精确匹配、纠错、补全、简拼、语言模型重排，全都折算成一个分数再排**，各类之间没有硬的先后；
评测集只量「第一个对不对」（top1），量不出「这种结果永远不许有」。一条离谱的结果在 top1 统计里只是少一条，
混在几千条里谁也看不出来。

## 2. 成熟输入法怎么做

读的是 librime（RIME）、libime（fcitx5 拼音）、libpinyin（ibus-libpinyin）的源码（2026-11 的 HEAD，只读不编）。
**只借思路，不抄代码**：它们的许可证（BSD-3 / LGPL）和本仓库（MIT OR Apache-2.0）不同。
标「推断」的是从代码推出来、没有直接看到的结论，其余都在源码里核实过。

### librime

- **表示**：音节图的每条边带一个拼写类型（正常、模糊音、简拼、补全、歧义），另有一个「是不是纠错」的标记和一个
  「可信度」（对数概率）。模糊音、简拼各罚 log 0.5，补全 log 0.05，纠错 log 0.01（`algo/calculus.cc`、`algo/syllabifier.cc`）。
- **精确的边一直在**：建图时先记下每个位置上精确匹配的音节，只有**不是**精确匹配的才标成纠错、加罚分；
  精确的那条边可信度为 0，和纠错边并存（`test/corrector_test.cc` 就测这个）。纠错边不参与决定「这个位置能不能走到底」，
  也就决定不了切分。
- **硬的分层，不只靠分数**：
  - 不同翻译器的候选先按「从哪开始」、再按「到哪结束（长的在前）」、最后才按质量排（`Candidate::compare`）：
    句首词永远排在盖住整段输入的候选后面；
  - 同一个结束位置里，精确匹配排在联想（没打完的词）前面，再比剩下没打的码长，最后才比分数（`compare_head_entries`）；
  - 正常拼写能走到底时，简拼类的边直接删掉。
- **纠错有名额**：一次最多出 4 个纠错候选（`max_corrections_`）。
- **整句只在需要时才造**：已经有一个精确、不靠纠错的词盖住整段输入时，不再拼整句（`has_reliable_phrase`）。
- **候选顺序**：整句 → 从长到短的词 → 第一个音节的单字。单字一直在。
- **整句解码**：每个位置按末词各留一条最好的（`poet.cc`）。

### libime（fcitx5 拼音）

- **表示**：模糊音、纠错、补全是标记位（`PinyinFuzzyFlag`）。解析输入时**带纠错解一遍、不带纠错再解一遍，结果合并进同一张图**：
  不纠错的切分永远在图里。罚分是软的（每处模糊 log10 0.5；纠错算 10 处，约 1000 倍）。
- **剪枝**：每个音节跨度最多留 40 个词，但**从输入开头起的跨度不剪**；束宽 20，每个词节点留一个最好的前驱。
  （推断：词节点本身不会丢，但句子中间某个精确的前驱排到 20 名以外时，那条精确的历史会丢。）
- **候选怎么拼**：先是最好的整句；然后从输入开头起的**不纠错的词全部无条件加入**；纠错的词只在精确词的分数窗口里、
  或者是单音节时才加；多个词拼的句首候选只要路径上有一处纠错就不要。去重时，同字同跨度的两条留没纠错的那条。
  候选数上限（15）**不管单音节的字**：第一个音节的单字永远在。
- **测试**：只测了候选不重复、某个词在不在，没有「纠错不能排在精确前面」这种顺序断言。

### libpinyin

- **表示**：纠错是解析表里的「非标准拼法」条目（`zhagn` → zhang），**只在这串字母本身不是合法拼法时才会用到**，
  不会和合法拼法竞争；解析是单一最优的动态规划，纠错距离只在最后打破平局。
- **没有显式的模糊、补全罚分**，靠读音频率的占比。
- **候选排序是严格分层的**：先按词长、再按拼音长、最后才按频率；第一个音节的单字永远在（排最后）。

### 共同的规矩

| # | 规矩 | 谁这样做 |
|---|---|---|
| P1 | 照着打的读法永远在：纠错、模糊只是**加**进来的候选，从不**替换** | 三家都是 |
| P2 | 纠错的代价远大于模糊、简拼（约 100–1000 倍 vs 2 倍） | librime、libime |
| P3 | 从输入开头起的精确词无条件进候选；纠错的要过分数门槛；带纠错的多词句首候选不要 | libime |
| P4 | 同字同跨度时留没纠错的那条 | libime、librime（去重留排在前面的） |
| P5 | 纠错候选有名额 | librime（4 个） |
| P6 | 已经有精确的整词盖住整段输入时不拼整句 | librime |
| P7 | 先按覆盖（用掉多少输入）分层，再比分数 | librime、libpinyin（硬分层）；libime（每个没盖住的音节重罚） |
| P8 | 第一个音节的单字永远在，候选数上限不管它们 | 三家都是 |
| P9 | 输入开头起的跨度不剪；剪枝按末词各留一条，不把不同的末词并掉 | libime、librime、libpinyin |
| P10 | 纠错不决定切分 | librime、libpinyin |

三家都**没有**「纠错不许排在精确前面」这种测试：它们靠的是结构（分层、名额、无条件加入），不是靠调分数再测。

## 3. WowType 现在怎么做

一次按键的流程（`core/src/lib.rs`）：

1. **音节图**（`graph.rs`）：全拼边；纠错边（相邻键替换、音节内对调、多按、中间漏按、跨音节对调，每条边纠一处）；
   末音节补全边（缺几个字母）。全拼走不通时另建简拼 / 全拼混简拼的图（`abbrev_graph`）。
2. **束搜索**（`beam.rs`）：每条边的代价 = 词典代价 + 语言模型 + `typo_cost`（8.0）× 纠错处数 + `completion_cost`（1.5）× 补的字母数
   + `abbrev_cost` / `tail_abbrev_cost`。`prune` 每个位置留 `beam_size`（20）个状态，按「末词 + 纠错处数」去重，
   纠错最少的状态另外至少留 4 个（`TYPED_RESERVE`，72bf8e2 加的）。
3. **`query_once`**：把路径变成候选，`nnlm_scores`（神经语言模型，以纠错最少的照着打的读法为基准）、`typed_reading_first`
   （纠错多的不排到纠错少的照着打的读法前面，按分数压）、`exact_syllable_first`（单音节输入：本音节的字 → 补全 → 纠错）。
4. **`pinyin_candidates`** 里按位置再挪：`protect_exact_input`（打全了的实在的词排第一）、`promote_picked`、
   `pin_single_initial`、原始串 / 英文、`prefix_on_syllable_boundaries` + `compose_candidates`（句首词和整句穿插，
   排第一的没纠错时纠错的放到句首词后面）、`append_more_candidates`（翻页长尾：同音词 → 句首词 → 单字 → 换切法的词……）。

## 4. 对照：哪里是「一个分数」，成熟引擎用的是「分层」

| 方面 | 成熟引擎 | WowType | 风险 |
|---|---|---|---|
| 纠错 vs 照着打 | 精确边一直在、纠错边不决定切分（P1、P10）；纠错候选有名额（P5） | 纠错边和精确边进同一个束搜索，靠 `typo_cost` 拉开；之后由 `typed_reading_first`（按分数）、`compose_candidates`（按位置）、本次加的 `typos_after_typed`（按位置）几处分别补救 | 任何一个后面按位置挪候选的步骤都可能绕过前面的补救（`sheihaiyo` 就是这样，见第 6 节）。规则散在好几处，每处的「照着打」定义还不完全一样 |
| 纠错的代价 | 约 log 0.01 ~ log 0.001，而且是额外一层 | `typo_cost` = 8（≈ log 0.0003），但词频、语言模型、神经语言模型的分数范围能到十几二十，一个罚分盖不住 | 高频字（的、得、是）附近的键最容易出事 |
| 句首词（前缀）对齐 | 从输入开头起的精确词无条件加入（P3） | 按**第一名**的音节边界筛（`prefix_on_syllable_boundaries`），第一名是纠错的时就按纠错的音节筛 | 第一名是纠错时，照着打的第一个音节的单字整个没了（`yusezhi`、`gaj`，本次修了） |
| 单字 | 永远在，不受上限（P8） | 翻页长尾补，但长尾也是按第一名的切法补；候选上限 1000 一般够 | 同上 |
| 补全 vs 精确 | librime 精确在前、再比剩下的码长（硬分层） | 补全每字母罚 1.5，单音节输入另有 `exact_syllable_first` 按位置分层，多音节输入只靠分数和 `protect_exact_input`（只认第一个打全了的词） | `typed_reading_first` 把补全出来的读法也当「照着打」的基准，后面的步骤又把补全的挪走了（`sheihaiyo`）；`qingkuan` 的「请款」、`fangxiangji` 的「芳香剂」排在补全的「情况」「方向键」后面（本次修了） |
| 同字同跨度 | 留没纠错的那条（P4） | 束搜索、句首词、长尾按代价去重：纠错读出来的同一个字更便宜就留纠错的 | `cunzai` 里没有「蹲」（cun）：纠错的 dun 便宜，照着打的被去重掉，纠错的又被筛掉（本次修了） |
| 名额 | 输入开头的精确词不受名额限制（P3、P9） | 句首词、长尾每个跨度的名额纠错词和照着打的词一起抢；整句名额同样 | 纠错出来的常用词把照着打的冷门字、整句挤掉（`weihuj` 接着上文打一个照着打的整句都不剩，本次修了） |
| 模糊音兜底 | 模糊音是和精确读音并列的一层，罚分固定（log 0.5），精确的永远在（P1） | 模糊音关着时 `fuzzy_fallback` 在第一名偏弱时补一两个模糊音的词，和其它候选按分数混排；`compose_candidates` 以前把它当成「打全了的整词」，比它差 3 以上的照着打的整句全当硬凑的筛掉 | 接着上文打 `ninke` 只剩「宁可」，照着打的「您可」整个没了（本次修了） |
| 简拼 | 正常拼写走得通就删简拼边 | 全拼有精确路径且有认识的词时不建简拼图（`run_query`），结构上已经分层 | 和成熟引擎一致 |
| 整句 vs 整词 | 有精确整词盖住整段输入就不拼整句（P6） | 照样拼，再由 `protect_exact_input`、`compose_candidates` 的 `JUNK_SENTENCE_MARGIN` 按分差筛 | 分差是调出来的阈值 |
| 语言模型 / 神经语言模型 | 不改变上面的分层，只在层内排序 | 加进同一个分数；72bf8e2 以后基准是照着打的读法，纠错路径不加分 | 层内排序没问题；跨层时还是一个分数 |
| 剪枝 | 输入开头的跨度不剪；按末词各留一条（P9） | 按「末词 + 纠错处数」各留一条，纠错最少的保底 4 个 | 和成熟引擎同一思路（72bf8e2 以后） |
| 测试 | 结构保证，测试少 | 本次加了逐键的不变量检查 | — |

**结论**：WowType 的问题不是某个权重调错了，而是「照着打的读法优先」「第一个音节的单字一直在」这类规矩没有一个统一的、
最后执行的分层，而是散在几个按分数或按位置挪候选的函数里，后一个能把前一个的结果冲掉。成熟引擎用结构保证
（精确的永远加入、纠错有名额、按覆盖分层），WowType 现在用不变量检查兜底，再逐步把规矩收拢（第 7 节）。

## 5. 不变量检查

`wowtype-eval --invariants`（`core/src/bin/common/invariants.rs`）把 `tools/eval/*.tsv` 里的每个输入**逐键**打一遍
（`c`、`ce`、`ceh`……），每个前缀在几种条件下各查一次：没有上文；用例自带的上文；脚本里固定加的上文（「我本地」）；
给了 `--nnlm` 时每种再带上神经语言模型查一次。双拼用例（`sp=`）不查。

| 规则 | 内容 | 对应的规矩 |
|---|---|---|
| `typed-first` | 输入能整个切成完整音节（不靠纠错、补全）时，第一个候选不是纠错出来的。例外：纠错以后音节更少（`shijain` 照字母读是 shi jia in，纠一处是「时间」）；照着打的音节词库里一个字都没有（`ng`） | P1 |
| `typed-first-partial` | 不靠纠错、只靠末音节补全能读通时（`ceh` = ce + h…），同上 | P1 |
| `first-syllable-chars` | 照着打的读法（不纠错，末音节可以补全）有两个以上音节时，第一个音节的单字在候选里。切法不止一种时（`kenengs` = ke neng s / ken eng s）只要第一个候选用的那种；第一个候选是纠错的，每种都要 | P3、P8 |
| `min-candidates` | 第一个音节是打全了的音节时，中文候选至少 min(9, 这个音节的常用单字数) 个 | P8 |
| `typed-kept` | 没有上文、不带模型时照着打的读法，加了上文或带上模型以后还在：是一个词时这个词还在；是几个词拼的整句时，至少还有一个照着打的整句 | P1 |
| `no-duplicates` | 没有字和用掉的键都一样的两条候选 | P4 |
| `completion-outranks-word` | 打全了、整个输入正好是一个常用词（词频 1000 以上、拼音和打的字母一字不差）时，补全出来的候选不排在它前面 | P7 |
| `typo-only-adds` | **用户的规矩**：把按错键纠错关掉再查一次，关掉时第一页的词（整词、句首词、单字）开着时都还在，关掉时排第一的照着打的读法开着时也还在（是几个词拼的整句时，至少还有一个照着打的读法） | P1、P3 |
| `typo-outranks-typed` | 关掉纠错时排第一的照着打的读法，开着时不排在纠错加进来的候选后面（音节更少的例外，同 `typed-first`） | P1 |
| `typo-flood` | **纠错有名额**：排第一的不是纠错出来的时（全拼、补全、简拼读得通），排在正常候选前面的纠错候选最多 3 个（`TYPO_QUOTA`），其余只能在整个列表的最后面 | P5 |
| `fuzzy-only-adds` | 同 `typo-only-adds`，关的是模糊音兜底 | P1 |
| `fuzzy-outranks-word` | 照着打的读法本身是词库里一个够常用的词（词频 ≥ 1000）时，模糊音兜底的词不排在它前面（`penyou` 出「喷油」「朋友」）。照着打只能几个字硬凑时（`shengme`）模糊音的词可以排第一，见第 6 节「模糊音兜底」 | P6 |
| `jianpin-only-adds`、`jianpin-outranks-typed` | 同上，关的是简拼；只查打全了的输入（`zg`、`wm` 本来就没有照着打的全拼读法，简拼就是照着打的） | P1 |

纠错、模糊音兜底、简拼三条是对比着查的：开着时前两页里有它加进来的候选，就把它关掉（`set_typo_correction`、
`set_fuzzy_fallback`、`set_jianpin_fallback`）再查一次。

怎么跑：

```bash
scripts/invariants.sh /usr/share/wowtype                                   # 和 CI 一样（不带模型）
scripts/invariants.sh /usr/share/wowtype --nnlm /usr/share/wowtype/nnlm.bin # 带神经语言模型（慢一倍多）
scripts/invariants.sh /usr/share/wowtype --inv-limit 0                      # 每条规则的违反全打出来
```

数据目录、模型所在目录不可写时脚本先复制到临时目录（载入时会在旁边写缓存）。逐键约 2.4 万个前缀，加上带上文的约 5 万次查询（带模型再翻一倍），
不带模型约两分半，带模型约十分钟。CI 的「排序评测（真实词库）」任务在排序评测后面跑它（复用编好的 `wowtype-eval`）。

**一条都不许违反。** 确实是对的、只是规则太死的，写进 `tools/eval/invariants-allow.tsv`（规则、输入、上文、理由四列），
不写理由不认；清单里的条目不再违反了，检查也会失败，提醒删掉。现在清单是空的。

写规则时踩过的坑（都是规则本身太死，已经改了规则，不是引擎的问题）：

- 一种输入有几种照着打的切法（`kenengs` = ke neng s / ken eng s，`hung` = hu ng / hun g…）：只要候选里第一个照着打的读法用的那一种的单字；
- 词库里一个字都没有的音节（`nia`、`ng`、`hm`）不算「照着打能读」：`zuinia` 照着打是 zui ni a，三个音节，纠一处的「最佳」两个音节，按「音节更少」的例外排第一不算错；
- 模糊音兜底的词（`zuijing` 的「最近」、`penyou` 的「朋友」）不算照着打的读法：规则查词库，词库里这个词真有这个读音才算；
- 翻页长尾里补全出来的词没有补全的标记（`shenghu` 的「圣皇」是 sheng huang）：「打全了的词」要拼音和打的字母一字不差；
- 「只能加」不管几个词硬凑的整句（`zenm` 的「谮吗」）：整句有名额、会换拼法，只要还有一个照着打的读法就行。

### 模糊音兜底：照着打是现成的词时让位（用户定的）

模糊音关着时，第一名偏弱就由 `fuzzy_fallback` 补一两个模糊音的词，分数高出一截就排第一。这有两种情况，用户定的规矩是分开对待：

- **照着打的读法本身是词库里一个够常用的词**（词频 ≥ `EXACT_PROTECT_MIN_FREQ`）：它排第一，模糊音的词紧跟在后面。
  `penyou`：喷油、朋友；`zuijing`：最精、最近；`lindai`：林带、领带；`tiexiang`：铁箱、贴现。照着打的没打错，模糊音的词只是「加」。
- **照着打只能几个字硬凑**（词库里没有这个读音的词，或者只有补全才凑得出词）：模糊音的词照旧排第一。
  `shengme`：什么（没有 sheng me 这个词，「声门」是补全）；`zhouba`：走吧（「周报」是 zhou bao，补全出来的）；`heishe`：黑色。

实现是 `fuzzy_after_exact_word`（`lib.rs`，和 `completions_after_exact_words` 用同一个「打全了的常用词」的判断）；用户选过的模糊音词不挪。
检查是硬规则 `fuzzy-outranks-word`。以前只报告的 `fuzzy-outranks-typed`（57 条）去掉了：里面除了上面第一种的几条，都是第二种，按规矩是对的。
回归集相应改了：`penyou` 期望「喷油」第一、「朋友」前两名，加了 `zuijing`；`shengme` → 什么 不变。排序评测其余各组不变（`mid` 多对一条）。

### 纠错有名额，最后一步统一执行（2026-11-28）

前面的规则只管「第一个候选」和「关掉纠错时有的，开着时还在」，管不到**纠错候选有多少、排在哪**。实际的候选列表里，
纠错出来的整词、整句成片接在第一页的句首词后面：`nishi` 第 12 到 36 个全是 n 当成 j、b、m 纠出来的「即使、笔试、及时、迷失……」，
ni 剩下的单字和换切法的词被压到第五页以后；`nihao` 有 14 个，`haode` 25 个。照新加的 `typo-flood` 规则量（自家用例逐键约 5 万次查询）：
**18645 次**查询里排在正常候选前面的纠错候选超过 3 个。用户看到的就是「一大片纠错出来的词排在正常的字词前面」。

改法是第 7 节第 3 条（名额，P5），做成整条管线的**最后一步**（`settle_corrections`，`pinyin_candidates` 的末尾，
在拼句首词、补长尾之后），后面再没有按位置挪候选的步骤能把它冲掉：

1. **让位**：纠错候选不排在音节数不比它多的照着打的读法前面（`yield_to_typed`，和 `typos_after_typed` 共用）。
   以前只和**第一个**照着打的读法比音节数：接着上文、带模型打 `chaikaibaozhua`，排在前面的照着打的读法是五个音节的
   「拆开抱住啊」，四个音节的纠错词「拆开爆炸」就算「音节更少」排了第一，可照着打本来也能读成四个音节。现在和列表里
   每一个照着打的读法比。让位以后整句名额可能已满，最好的一条纠错整句照样留在句首词后面（`compose_candidates`）。
2. **名额**：排第一的不是纠错出来的时，纠错候选只留最前面的 3 个在原来的位置，其余挪到整个列表的最后（不删，纠错只「加」）。
   排第一的本身就是纠错的（`zhognguo` 读不通、`jintiam` 纠了以后音节更少）时不限名额。用户选过的纠错词不挪、不占名额。
   名额取 2、3、4 时各组评测的 top1 / top3 / top9 逐项一样（包括 chime 的错键用例）：第 4 个以后的纠错候选本来就没有排进前 9 的。

「照着打的读法」现在只有一个定义（`is_typed_reading`），`typos_after_typed` 和最后一步用同一个。

同一次还查出两处「纠错替换了照着打的候选」，`typo-only-adds` 以前只比字、看不出来（字一样、用掉的键不一样）：

- **同字的纠错词把照着打的句首词去重掉了**（`compose_candidates`）。接着打下一个音节的第一个字母时最常见：`lingjias`
  的句首词「凌驾」（ling jia，s 留着接着打）和把 s 当成多按的键纠出来的整词「凌驾」字一样，留下的是纠错的那条，
  排在句首单字后面，选它还会把刚打的 s 吞掉。现在同字时留照着打的句首词（P4）；排第一的那条不动
  （`chaoxik` 的「抄袭」纠了以后音节更少，是正经候选）。
- **末音节补全得长时句首词整个不筛**（`prefix_on_syllable_boundaries`）。第一名的音节总长比字母多两个以上就当成简拼、
  不按音节边界筛：`daziy` 的第一名「打字员」（y → yuan）就中了，纠错出来的句首字「带、代、待」（dai）留着、排到 da 的常用字前面，
  「大」「打」反而被名额挤掉。现在末音节前面的音节都和字母对得上时照常筛。

`typo-only-adds` 相应加严：关掉纠错时第一页的词，开着时要么用掉的键一样多、要么不是纠错加的，才算「还在」
（开着时排第一的那条除外）。加严以后在改之前的引擎上是 1249 条，改完 0 条（不带模型）。

修之后 `typo-flood` 不带模型时 0 条。拿引擎没见过的输入（chime 的盲测整句，851 条、逐键 2.7 万个前缀）各查一遍，结果见本次 PR 的说明。

### 其它几种机制

- **双拼**：按错键纠错和模糊音兜底在双拼下本来就关着（`run_query`、`prefix_candidates`、`append_more_candidates` 里的
  `typo = typo_correction && !shuangpin`、`fuzzy_fallback && !shuangpin`），补全只给悬空的声母，简拼只在全拼走不通时用，
  结构上不会替换照着打的读法。不变量检查不跑双拼用例（`sp=`），这一点是读代码得出的，没有逐键验证。
  双拼的简拼（`ShuangpinAbbrev`，#268）照同一条规矩：按双拼读得通、有词时，双拼读出来的候选一个不少、先后不变，
  简拼的词（最多 6 个够常用的整词）插在第 5 个后面（`add_shuangpin_abbrev_words`）；读不通时才整个按简拼出。

- **神经语言模型重排**：只在束搜索的路径里重排，72bf8e2 以后以照着打的读法为基准；带 `nnlm.bin` 的检查里
  `typed-kept`（加了模型照着打的读法还在）和其余规则见上表。
- **会话层**（`core/src/session.rs`）：读了候选怎么拼（`compute_candidates`）、翻页、选句首词（`choose_now`）、学习（`learn`、
  `learn_composed`）、上文（`set_context`、`check_context`）。会话只往引擎的候选里**加**东西（emoji 推荐插在第 3 个、按键 emoji、
  日期时间），不删不重排引擎的候选；唯一挪位置的是日期时间的触发词（打 `shijian` 时把「时间」挪到第一），挪的就是照着打的那个词。
  选了纠错出来的词，记的是纠错后的拼音（`record_selection_with_pinyin(词, 纠错后的拼音)`），不会把「ce → 的」学进去；
  `promote_picked` 只提前没纠错、没补全、不是简拼的选过的词，所以选过一次纠错词也不会让它下次排到照着打的前面。
  这一层没查出要改的地方；逐键的会话级检查（翻页、选了句首词以后剩下的部分）没有做，`scripts/addon-test.sh` 的按键用例照常全过。

## 7. 还没做的：把规矩收拢成分层

不变量检查只能事后兜底。照成熟引擎的做法，建议按这个顺序把散着的补救收拢（每一步都要 `scripts/eval.sh` 持平、
`scripts/invariants.sh` 零违反）：

1. **一个统一的「照着打」定义**。现在 `typed_reading_typos`（路径级）、`typos_after_typed`（候选级）、
   `prefix_on_syllable_boundaries` 里的照着打的读法、`exact_syllable_first` 的 `exact` 各写各的。
   束搜索出来时就在 `Candidate` 上记一个「层」（精确 / 补全 / 简拼 / 纠错），后面所有步骤只看这个字段。
2. **最后一步统一按层排**（像 librime 的 `Candidate::compare`）：层与层之间按层，层内才按分数和现有的按位置规则。
   这样 `protect_exact_input`、`compose_candidates`、`exact_syllable_first` 里各自的「纠错放后面」就可以删掉，
   也不会再出现后一步冲掉前一步的情况。纠错层的例外（音节更少的整词：`shijain` → 时间、`tianqu` 的「天气」放第二）
   作为显式的规则写在这一步，而不是靠分数碰巧。
3. ~~**纠错候选有名额**（P5）~~：做了，见第 6 节「纠错有名额，最后一步统一执行」（`settle_corrections`、规则 `typo-flood`）。
   第 1、2 条做了最小的一步：「照着打」的定义收成一个 `is_typed_reading`，纠错的让位和名额放在最后一步执行；
   其余几处（`protect_exact_input`、`compose_candidates`、`exact_syllable_first` 里各自的规则）还没有收拢。
4. **句首词不再按第一名的切法筛**，改成 libime 的做法（P3）：从输入开头起、落在照着打的任一种切法的音节边界上的精确词无条件加入，
   纠错的句首词只在分数窗口里加。本次的修复（第 1、7 处）是这一步的最小版本。
5. **有精确整词盖住整段输入时不拼整句**（P6），代替 `JUNK_SENTENCE_MARGIN` 这个按分差筛的阈值。
6. **评测集加逐键的整句用例**：现在 `daily.tsv` 只测整句打完那一刻。不变量检查已经逐键跑，但只检查规则，不检查 top1。

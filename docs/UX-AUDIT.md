# 指标对产品体验的影响审查

2026-11-07。审查对象：按错键纠错、补全（半成品）、句首词、英文词这几项改动。
它们都会往候选里加东西、改动排序，指标涨了不等于用户体验好了。

## 判断标准

**用户按空格上屏的是第一个候选。** 所以：

- 用户已经把拼音打全、而且打的就是一个实在的词时，第一个必须是它。
  换成别的词，用户一按空格就是打错字，还得删掉重打——这是最坏的结果。
- 用户打到一半时，想要的词排第二只是多按一个数字键，或者再打一个字母。
- 第一页（插件里 9 个）是稀缺位置，塞进没用的候选等于把有用的挤到第二页。

按这个标准，「截断 1 个字母 top1」这种指标要分开看：截完的字母本身就是另一个词时
（`zhonggu` 就是「中古」），它奖励的恰恰是「把用户打全的词换掉」。

## 发现的问题

### 1. 打全了的词被高频补全抢走（main 上就有，这次修了）

| 输入 | 改前第一个 | 应该是 |
|---|---|---|
| `zhongdi` | 重点（zhong dian 的补全） | 种地 |
| `ka` | 看（kan） | 卡 |
| `ya` | 要（yao） | 呀 |
| `qin` | 请（qing） | 亲 |
| `beiji` | 北京 | 北极 |
| `anni` | 按钮 | 按你 |
| `dire` | 敌人 | 地热 |

原因：补全按「多打的字母数」扣分（每个 1.2 nats），但两个词的词频可以差几十上百倍
（重点 50 万 vs 种地 2.5 万，差 3 nats），扣分永远压不住。

**为什么以前的评测没发现**：完整输入的用例只取频次前 5000 的词，这些词本身就是最高频的，
很少被别的词补全抢走；而「rank1 99.2%」里漏掉的 3 例正是 `ka`/`ya`/`qin`，被当成了正常误差。
中低频词（频次排 3 万到 30 万名）的完整输入 top1 只有 95.5%。

**修法**（`core/src/lib.rs` 的 `protect_exact_input`）：精确全拼、整个输入是一个词
（或最后一个词至少两个字）、词频不低于 1000 时，排在它前面的补全/纠错候选挪到它后面。
试过但否掉的方案：

- 只按分数差决定保不保护（差太多就不保护）：`按你` `实弹` `不敏` 又被抢走，否掉。
- 「最后一个词至少两个字」就保护，不看前面：`miotuoche` 会出「密哦 | 拖车」，
  `congshanruli` 出「从善 | 入理」而不是「从善如流」。改成：多个词拼的精确结果只和
  开头一样的拼凑候选比，整词盖住全部输入的不动。

### 2. 整个输入是一个词时被单字拼凑压下去（这次修了）

`shidan` → 是但，`lashi` → 啦是，`dejian` → 的见，`tazhong` → 他中。
单字频次高，乘起来比词还高。整个输入正好是一个词时，单字拼凑的候选排到它后面。

### 3. 单音节输入的第一页塞满拆开音节的字（这次修了）

`dan` 的候选里有 大 打 答 达 饿 呃，`xian` 里有 下 吓 夏 侠，`qin` 里有 起 气 啊 阿——
都是句首词候选把一个打完的音节拆开了（dan → da + n）。而且句首词是在候选上限之外追加的，
插件里候选总数能到 30 个。

现在句首词只在多音节输入里给、只在音节边界上切，总数不超过上限。

### 4. 长句的第一页被句首词占满（这次修了）

长句以前在第二位插入全部句首词（最多 12 个），第二、三个整句候选被挤到第二页。
现在：整句、最好的句首词（整句开头最长的那段，`我今天晚上要加班` → `我今天晚上`）、
再 4 个整句、再 2 个句首词。

### 5. 本身就是拼音的英文词排第 3（这次改了）

`fan` `she` `xi` `Chen` 排第 3，把常用字挤后。改成第 6，前 5 个留给中文。
不是拼音的（`hello` `github`）照旧排第一。

## 改完以后各项的副作用

「改前」是 main 分支，「改后」是现在。每组几百例，rime-ice 55 万词库 + 英文词表。

| 场景 | 改前 top1 / top3 | 改后 top1 / top3 | 说明 |
|---|---|---|---|
| 完整输入，常用词 | 100 / 100% | 100 / 100% | |
| 完整输入，中低频词 | 95.5 / 99.8% | 99.0 / 100% | 问题 1、2 |
| 最高频同音词 | 99.2 / 100% | 100 / 100% | ka/ya/qin |
| 第 2 高频同音词（top3） | 98.0% | 98.0% | 句首词、英文没挤掉同音词 |
| 截断 1 字母，截完不是词 | 100 / 100% | 99.5 / 100% | |
| 截断 1 字母，截完正好是另一个词 | 75.5 / 91.5% | 12.8 / 93.6% | 有意为之：精确词第一，补全第二 |
| 截断 1 字母，中低频词 | 89.8 / 97.5% | 89.0 / 97.0% | |
| 按成相邻键 | 0 / 0% | 85.7 / 90.1% | |
| 两键按反 | 0 / 0% | 93.0 / 96.5% | |
| 多按一个键 | 0 / 0% | 95.9 / 97.7% | |
| 漏按一个键 | 14.0 / 16.9% | 33.2 / 44.0% | 见下 |
| 长句 | 16 / 20% | 72 / 80% | |
| 日常句子（80 句） | 5.0 / 6.2% | 85.0 / 90.0% | |
| 简拼 | 94.3% | 94.3% | |

其他检查：

- **纠错会不会改坏打对了的输入**：中低频词、最高频同音词、低频词三组，纠错开和关的 top1
  完全一样。纠错只在「不纠就解析不完」或「纠完明显更常见」时才排到前面，
  而且打全了的实在词（问题 1 的规则）不会被纠错结果抢走。
- **长句整句没中时能不能补救**：日常句子和长句两组整句没中的 19 例里，14 例前 4 个
  候选里有对的开头，选它再接着打。
- **延迟**：逐键最慢 1.5 ms（全量词库，含纠错和句首词）。

## 还没解决

- **漏按一个键只有 33%**：少一个字母时剩下的常常正好是另一个合法拼音（`beiji` 既是「北极」
  也可能是漏了 g 的「北京」），按问题 1 的规则精确词排第一，纠错排第二。没有上下文就只能这样。
- **同音词靠上下文选**：`zaitaolun` 出「在讨论」不出「再讨论」，`renleishi` 出「人类是」
  不出「人类史」，`weifahuo` 出「违法或」不出「未发货」。要真正的语言模型，词频和规则解决不了。
- **截断后正好是另一个词的场景**：`zhonggu` 现在是「中古」第一、「中国」第二。
  如果实测发现用户常在这里按空格，可以考虑让「词频差上百倍」时补全排第一，但要先有真实使用数据。

## 怎么复现

```bash
# 中低频完整输入（关键：--skip 跳过常用词，否则看不出问题 1）
python3 tools/make_eval.py lexicon.tsv --skip 30000 --top 300000 --count 400 > mid.tsv
# 截断 1 个字母
python3 tools/make_eval.py lexicon.tsv --skip 30000 --top 300000 --count 400 --truncate 1 > midtrunc.tsv
# 跑评测：会列出 top1 被谁占了（补全 / 纠错 / 原始串或英文 / 句首词 / 同音排序）
cargo run --release -p wowtype-core --bin wowtype-eval -- \
    --lexicon lexicon.tsv --english english.txt --eval mid.tsv --k 3 --show-top1
```

单元测试 `exact_word_is_not_overridden_by_completion_or_typo`、
`prefix_candidates_do_not_split_a_syllable` 和插件按键测试（`zhongdi`、`ka`、`dan`）
钉住了上面几条规则。
